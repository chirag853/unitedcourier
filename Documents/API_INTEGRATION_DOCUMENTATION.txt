============================================================

Status:

Code location:
- app/Http/Controllers/customerController.php
- Function: sendOtpViaSms($mobile, $otp)
- Called from: checkPhone(Request $request)

Route flow:
1. Frontend/customer login sends phone number to:
   POST /customer/check-phone
2. Backend customer ko phone_number se search karta hai.
3. 6 digit OTP generate hota hai.
4. OTP session me store hota hai:
   - login_otp
   - login_phone
   - login_otp_expires_at
5. AuthKey SMS API call hoti hai.
6. Customer OTP verify karta hai:
   POST /customer/verify-otp

External endpoint:
- GET https://api.authkey.io/request

Query parameters used:
- authkey: config('services.sms.authkey')
- mobile: customer phone number
- country_code: config('services.sms.country_code')
- sid: config('services.sms.sender_id')
- otp: generated OTP

Config source:
- config/services.php
  - services.sms.authkey -> env('SMS_AUTHKEY')
  - services.sms.sender_id -> env('SMS_SENDER_ID', default '28102')
  - services.sms.country_code -> env('SMS_COUNTRY_CODE', default '91')

.env keys:
- SMS_AUTHKEY
- SMS_SENDER_ID
- SMS_COUNTRY_CODE

Request method:
- cURL GET request.

Timeout:
- 30 seconds.

Response handling:
- Code logs HTTP code and body.
- Function returns true unless cURL error occurs.
- Current code does not validate provider success response deeply.

Error handling:
- cURL error is logged as "SMS cURL error".
- If SMS sending fails, OTP is logged as warning for development/testing.

Security/production note:
- OTP log fallback should not be used in production logs.
- Auth key should remain in .env only.

4. UPS OAUTH TOKEN API
============================================================

Purpose:
- UPS API ke liye Bearer access token generate karna.

Endpoint:
- POST https://onlinetools.ups.com/security/v1/oauth/token

Auth:
- HTTP Basic Auth:
  - username/client_id
  - password/client_secret

Body:
- Form encoded:
  grant_type=client_credentials

Headers:
- Laravel Http::withBasicAuth() sets Authorization Basic header.
- asForm() sets form body.

Token functions:
1. getUpsAccessToken()
   - Uses env:
     - UPS_CLIENT_ID
     - UPS_CLIENT_SECRET
   - Cache key: ups_access_token
   - Intended for UPS rate/token use, but getUpsRate currently does local DB rates.

2. getUpsShipAccessToken()
   - Uses hardcoded credentials in controller.
   - Cache key: ups_ship_access_token
   - Used by UPS Ship API calls.

Token caching:
- expires_in response field is used.
- TTL = expires_in - 60 seconds.
- Minimum TTL = 60 seconds.

Expected successful token response fields:
- token_type
- issued_at
- client_id
- access_token
- expires_in
- status

Error handling:
- If token HTTP response fails, logs UPS token response body.
- If access_token missing, logs full body.
- Throws exception; caller returns error response.

Security note:
- getUpsShipAccessToken() currently has UPS credentials hardcoded in code.
- Recommended: move to .env keys like UPS_SHIP_CLIENT_ID, UPS_SHIP_CLIENT_SECRET, UPS_SHIPPER_NUMBER.

5. UPS SHIP API - DIRECT PROXY ROUTE
============================================================

Status:
- Active route exists.

Route:
- POST /customer/ups-ship
- Route name: customer.ups.ship

Controller function:
- createUpsShipment(Request $request)

Purpose:
- Frontend/full UPS payload ko backend proxy ke through UPS Ship API par send karna.

External endpoint:
- POST https://onlinetools.ups.com/api/shipments/v2403/ship

Request input:
- Backend request ka full payload directly UPS ko forward karta hai:
  $payload = $request->all()

Headers sent to UPS:
- Content-Type: application/json
- Accept: application/json
- Authorization: Bearer {UPS token}
- transId: unique id generated by uniqid('ship_', true)
- transactionSrc: unitedcourier

cURL settings:
- CURLOPT_RETURNTRANSFER: true
- CURLOPT_POST: true
- CURLOPT_POSTFIELDS: json_encode($payload)
- CURLOPT_TIMEOUT: 60
- CURLOPT_SSL_VERIFYPEER: false

Successful response condition:
- HTTP status 2xx
- JSON response contains ShipmentResponse

Success JSON returned to frontend:
- success: true
- shipmentResponse: UPS ShipmentResponse object

Error extraction checks:
- decoded.response.errors[0].message
- decoded.ShipmentResponse.Response.Error[0].ErrorDescription
- decoded.Fault.detail.Errors.ErrorDetail.PrimaryErrorCode.ErrorDescription

Failure JSON returned:
- success: false
- message: extracted or generic error
- rawResponse: decoded UPS response

Logging:
- Request payload logged, truncated to first 2000 chars.
- UPS response logged, truncated to first 2000 chars.
- Non-JSON responses logged separately.

6. UPS SHIP API - MANIFEST FLOW
============================================================

Status:
- Active.

Trigger:
- Customer view-all-shipments page.
- Single manifest route:
  POST /customer/manifest
- Bulk manifest route:
  POST /customer/bulk-manifest

Precondition:
- Shipment must be in "packed" status.

Workflow:
1. Customer creates shipment:
   POST /customer/create-shipment
   Status starts as draft.
2. Customer pays:
   POST /customer/pay-now
   Status becomes ready.
3. Print label/pack action:
   POST /customer/mark-packed
   Status becomes packed.
4. Manifest:
   POST /customer/manifest
   Backend checks selected courier service network.
5. If network is not Ship Global, UPS flow is used by default.

Network routing logic:
- shipping_method resolved via resolveShippingMethod($shipper)
- courier service found via findCourierService($shippingMethod, $shipperId)
- network = strtolower(trim($courierService->network))
- if network is "ship global" or "shipglobal": Ship Global API
- else: UPS API

UPS payload builder:
- buildUpsShipPayloadFromDb($shipper)
- Reads:
  - shipper_info
  - consignee_info
  - package_dimension
  - create_shipment fallback
  - courier_services
- Delegates to:
  - buildUpsShipPayload($validatedData, $service)

Shipping method fallback order:
1. shipper_info.shipping_method
2. create_shipment.shipping_method
3. package_dimension.shipping_method
4. first row in courier_services table

Courier service matching tiers:
1. Exact method match
2. Case-insensitive method match
3. str_contains partial match
4. Word-by-word normalized match, including abbreviation support
5. Collapsed-string match

UPS hardcoded shipper details in payload:
- Name: SANDEEP KAPUR
- AttentionName: United
- CompanyDisplayableName: UWC
- Phone: masked in this doc
- Address:
  - 218 WEST 37 STREET 6TH FLOOR
  - NEW YORK
  - NY
  - 10018
  - US

UPS shipper number selection:
- If courier_services.weight contains OZS or OZS/LBS saver logic:
  - Saver services use shipper number X19700
- LBS services use shipper number 1255AK

PaymentInformation:
- ShipmentCharge.Type: 01
- BillShipper.AccountNumber: selected shipper number

Service code:
- Default from courier_services.scode.
- For weight = OZS/LBS:
  - If max package weight converted to lbs is > 0 and < 1:
    service code = 92
    weight unit = OZS
    description = Ground Saver Less than 1 lb
  - If max package weight >= 1 lb:
    service code = 93
    weight unit = LBS
    description = Ground Saver 1 lbs or grater

Weight conversion:
- OZS: kg * 35.274
- LBS: kg * 2.20462

Package payload:
- Description: Documents
- Packaging.Code: 02
- ReferenceNumber:
  - Code: 9S
  - Value: ORDER12345
- PackageWeight.UnitOfMeasurement.Code: OZS or LBS
- PackageWeight.Weight: converted weight
- Dimensions.UnitOfMeasurement.Code: IN
- Dimensions Length/Width/Height:
  - Uses package_dimension values.
  - If missing, fallback: 10 x 8 x 4.

Important note:
- DB fields are named length_cm/width_cm/height_cm, but UPS payload sends them as IN. Current code does not convert cm to inch.

Label format:
- LabelSpecification.LabelImageFormat.Code: PDF

UPS response storage:
- Model: App\Models\ShipmentTracking
- Table: shipment_tracking
- Stored fields:
  - customer_id
  - shipper_id
  - create_shipment_id
  - response_status_code
  - response_status_description
  - transaction_identifier
  - customer_context
  - shipment_identification_number
  - transportation_charges_currency
  - transportation_charges_amount
  - service_options_charges_currency
  - service_options_charges_amount
  - total_charges_currency
  - total_charges_amount
  - billing_weight_uom
  - billing_weight
  - package_results
  - raw_response
  - status

Tracking number extraction:
- ShipmentResults.PackageResults.TrackingNumber
- fallback: ShipmentResults.ShipmentIdentificationNumber

After success:
- shipment_tracking is updateOrCreate by shipper_id.
- shipper_info.status becomes manifested.
- tracking table gets a manifested status row.

8. INTERNAL RATE API - /customer/ups-rate
============================================================

Status:
- Active internal endpoint.
- Despite route/function name, current implementation does not call UPS external rate API.
- It calculates rate cards from local database tables.

Route:
- POST /customer/ups-rate
- Route name: customer.ups.rate

Controller:
- customerController@getUpsRate

Frontend location:
- resources/views/customer/create-shipment.blade.php
- Rate Calculate button triggers fetch('/customer/ups-rate')

Inputs:
- service_id
  - Empty means "all services mode"
  - Non-empty means single-service mode
- total_weight
- consignee_state

Auth:
- Requires logged-in customer guard.
- If not logged in returns 401.

Tables/models used:
- courier_services
- courier_rates
- zones
- customers

Zone lookup:
- Zone::where('zone_code', consignee_state)->first()

All-services mode:
- Triggered when service_id is empty.
- Loops all courier_services ordered by network, method.
- Fetches customer-specific courier_rates first:
  - customer_id = logged in customer id
  - service_id = current service id
- If no customer-specific rates:
  - fallback customer_id = 0 default rates
- Filters by:
  - total_weight between wt_range_start and wt_range_end
  - zone_no null/0 OR zone_no equals selected zone id

Single-service mode:
- Finds CourierService by service_id.
- Fetches customer-specific rates, fallback default rates.
- Same weight and zone filtering.

Response fields:
- success
- customer_exists
- customer_name
- selected_zone
- all_rates
- matched_rate for single service
- service metadata for single service

Each rate includes:
- rate_id
- service_id
- method
- method_display
- network
- method_code
- tat
- delivery_days
- scode
- price
- zone_no
- zone_name
- zone_code
- fuel_charge
- fuel_percentage
- gst_percentage
- gst_amount

Frontend behavior:
- Builds selectable rate comparison cards.
- User selects service via radio.
- Selected service_id, service_rate_id, fuel, GST, total price are appended to create-shipment FormData.

Important note:
- If live UPS rates are required later, this endpoint name may be confusing. It currently means "local courier rate calculator".

- AdminController@generateLabel

Purpose:
- Return PDF label as base64.
- Priority:
  1. Use shipment_tracking.raw_response label from UPS/Ship Global.
  2. Fallback to locally generated Dompdf label.

Request:
- shipment_id: shipment_invoice.id

- Checks response_status_description contains "success".
- Looks in:
  - raw_response.ShipmentResults.PackageResults

  - trackingRecord.package_results
- Supports:
  - ShippingLabel.ImageFormat.Code
  - ShippingLabel.GraphicImage
  - LabelImage.LabelImageFormat.Code

- GraphicImage is returned directly as PDF base64.

- Paper: [0, 0, 400, 600]

Ship Global label extraction:
- Checks response_status_description contains "Ship Global".
- Looks for:
  - raw_response.data.pdf_base64
  - raw_response.pdf_base64

Fallback label:
- Queries shipment_invoice, shipper_info, customers, consignee_info.

- Dompdf paper: [0, 0, 280, 400]

Response:
- success

- source:
  - shipment_tracking

18. KNOWN RISKS / BUGS / IMPROVEMENTS
============================================================

1. Hardcoded secrets:
- UPS ship credentials hardcoded.
- Ship Global email/password hardcoded.
- Delhivery token hardcoded.
- Existing Documents/credentials.txt contains sensitive values.
- Move all to .env and rotate leaked credentials.

2. SSL verification disabled for UPS cURL:
- CURLOPT_SSL_VERIFYPEER => false
- Should be true in production.

3. UPS dimensions:
- DB columns are cm but UPS payload says IN.
- Convert cm to inches or rename fields/ensure UI collects inches.

4. Ship Global package_weight:
- Variable says kg, payload sends actual_weight_kg * 1000.
- Confirm provider expects grams.

5. Country mapping:
- Unknown destination defaults to US.
- This can create wrong international shipments.

6. /customer/ups-rate naming:
- It is local DB rating, not UPS live rating.
- Rename route/function later or document in UI/code comments.

7. AuthKey SMS success:
- Code returns true even if provider body says failure.
- Should parse response and fail when provider indicates error.

8. OTP logs:
- OTP warning log fallback should be disabled in production.

9. Delhivery payload:
- pickup/shipment field mapping should be verified with Delhivery docs.
- pkg_length appears referenced but not selected in query; code selects length_cm but payload uses pkg_length, so shipment_length may be 0.

10. Label handling:
- UPS GIF/image labels are converted via Dompdf.
- For thermal labels, native ZPL/EPL should be handled differently if needed.

11. Manual Ship Global label:
- If Ship Global returns order_number but no pdf_base64, app manifests successfully but label may fall back to local Dompdf.

============================================================
21. END-TO-END FLOW SUMMARY
============================================================

Customer creates shipment:
1. Customer fills create-shipment form.
2. Rate cards are loaded from /customer/ups-rate using local DB.
3. Customer selects a rate/service.
4. Form posts to /customer/create-shipment.
5. App creates:
   - shipper_info
   - consignee_info
   - package_dimension
   - csb_information
   - shipment_invoice
   - shipment_invoice_items
   - create_shipment
   - tracking draft row

Customer pays and prepares shipment:
1. /customer/pay-now deducts wallet and sets ready.
2. /customer/mark-packed sets packed.

Manifest:
1. /customer/manifest or /customer/bulk-manifest.
2. App resolves courier service network.
3. If Ship Global:
   - token API
   - addOrder API
   - store order/tracking
4. Else UPS:
   - UPS OAuth token
   - UPS Ship API
   - store charges/label/tracking
5. App sets status to manifested.

Admin delivery:
1. Admin assigns delivery.
2. If DDU:
   - Delhivery CMU API called.
3. App sets assigned_for_pickup tracking/status.

Label:
1. Admin generate-label tries carrier label from shipment_tracking.
2. If missing, Dompdf fallback label is generated.
